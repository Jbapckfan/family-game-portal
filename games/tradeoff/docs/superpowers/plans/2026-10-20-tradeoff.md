# Tradeoff Implementation Plan

> **For agentic workers:** Use the stated isolated file ownership for parallel work; verify the integrated experience before publication.

**Goal:** Ship a complete daily word game with clear rules, a satisfying interaction, and reliable progress.

**Architecture:** Static ES modules split into content, a pure engine, and DOM UI. Buildless Sites hosting with a tracked identity.

**Tech Stack:** HTML, CSS, browser JavaScript, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-20-tradeoff-design.md`

## Global Constraints

- Six common five-letter words; each starting word differs from its answer in exactly one position.
- One six-letter cycle with unique outgoing letters; par is five swaps.
- No runtime dependencies or external services for playing.
- Daily date is America/Chicago; epoch is 2026-10-20.
- Practice and revealed results do not earn daily win streaks.
- UI remains usable on a phone and with a keyboard.

## Review Focus

- Arbitrary bad swaps must not strand the last unsolved word.
- Broken or unavailable browser storage must not prevent play.
- Opening a finished or revealed save must preserve the correct result.
- Midnight rollover and DST must preserve puzzle identity.
- Dialogs and rerendered tiles must preserve accessible focus and truthful live feedback.

### Task 1: Content and engine

Files: `dist/puzzles.mjs`, `dist/engine.mjs`, `tests/puzzles.test.mjs`, `tests/engine.test.mjs`.

- [ ] Write and run failing invariant tests for board solvability and game transitions.
- [ ] Implement the curated collection and pure state/date/stats/share functions using the documented API in the design brief.
- [ ] Run `node --test tests/*.test.mjs`; require zero failures.

### Task 2: Interface and persistence

Files: `dist/index.html`, `dist/styles.css`, `dist/app.mjs`, `dist/icon.svg`, `dist/manifest.webmanifest`.

- [ ] Implement the mobile-first board, instruction card, selection, swaps, locks, undo, hints, and sounds.
- [ ] Add daily/practice selection, local saves, stats, results, reset/reveal confirmations, and clipboard fallback.
- [ ] Verify module syntax and exercise the complete play flow in browser preview, including help, practice, undo, hints, win, and refresh.

### Task 3: Review and publication

- [ ] Obtain an independent review of invariants, state, UX, and accessibility.
- [ ] Fix material findings and run the full suite and syntax checks.
- [ ] Use the source helper to push and package the exact verified state.
- [ ] Deploy the private Site and report the returned successful URL and material limits.
