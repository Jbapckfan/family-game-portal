# Native app implementation contract

The iOS 17+ app launches 32 bundled games. Eight retain Alford Daily development credit: Ringcount, Switchpath, Counterpart, Shortlist, Second Sense, Sideways, Tradeoff, and Inbetween. Six retain Kimi development credit: Cairn, Morph, Tangle, Hunch, Circuit, and Quartet. Six carry “Concept by DeepSeek · Built by Alford Daily”: Twin Hive, Spare, Rung, Cipher, Trail, and Split. Quadra retains “Developed by Qwen”; Logic Lattice, Syntax Siege, Memory Maze, Pattern Prism, and Territory Tactics carry “Concept by Qwen · Built by Alford Daily.” Dovetail, Splice, Sprout, Tangle, Keystone, and Tumbler retain “Developed by Claude.” Ringcount and Switchpath lead the native home. All / Alford Daily / Kimi / DeepSeek / Qwen / Claude filters change the visible cards while the daily completion summary covers the entire collection. Creator filters scroll horizontally when needed, and long credit lines wrap.

SwiftUI owns navigation, Today, daily completion, a local record, settings, reminders, share presentation, and haptics. WebKit owns each existing game's rules and interaction. All game pages use `alford://app/games/<slug>/` and the persistent default WebKit data store. Imported game slugs use the `kimi-`, `deepseek-`, `qwen-`, or `claude-` prefix, so the two games named Tangle retain distinct routes and saved results. The custom resource handler reads only the bundled `Web` folder, allowing the 32 game directories, constrained shared Kimi resources, and exactly `core.mjs`, `common.mjs`, and `styles.css` in the flat `deepseek-runtime` namespace shared by DeepSeek, Qwen, and Claude entries. Those eighteen game directories contain only four required runtime files plus optional local styles; development tests and documents are excluded. Shared assets are not navigable game documents. Navigation cannot load a remote site.

The `alford` script-message handler accepts only a main frame from that local origin and the active catalog game's path. Progress payloads update a native ledger for daily mode and cumulative game statistics for either mode. Practice never creates a daily result. The first terminal result for a game/date is preserved. A native daily streak means solving at least one of the 32 dailies on consecutive Central calendar days. Existing game identifiers and saved native preferences/results remain compatible; adding a creator does not rename earlier games or reset their progress.

The bridge carries `progress`, `share`, `haptic`, and `gamePreference` messages. It never accepts arbitrary JavaScript, file paths, URLs to open, notification commands, or purchase commands. The native code injects an environment marker containing a catalog-validated game ID and boolean game preferences. Later preference updates use `callAsyncJavaScript` arguments; user-controlled text is never interpolated into JavaScript.

Reminders default off. Only the Settings enable action requests notification authorization. The selected repeating time is explicitly Central time. StoreKit code is present, but production commerce and its UI default off. A separate debug-only scheme and launch argument enable local StoreKit testing with a local product; the normal app has no purchase button, advertising SDK, or product lookup.

The 29 XCTest methods specify date boundaries, catalog attribution and filtering, exact Claude puzzle-bank counts, untrusted bridge rejection, first-terminal records, practice isolation, six- and fourteen-game snapshot migration, resource traversal defenses, and actual offline WebKit loading across all 32 games. A Python validator checks the project graph, resource references (including the new local module imports), shared schemes, privacy declaration, and complete Web bundle. Structural checks do not compile Swift. Xcode tests and device verification remain necessary on a Mac; consult the actual workflow result for the revision being released.

## Local favorites and hidden games

The home offers Favorites only and Show hidden controls. Star and Hide/Unhide actions are separate from each card’s navigation link; the active game also has a native star button and a Hide/Unhide menu action. These filters affect visible daily, featured, bonus, and collection entries without replacing the prepared daily set. Collection records continue to include every daily game. Hiding a favorite retains its star; Show hidden makes it possible to restore the game.

`ProgressStore` persists `GamePreference { favorite, hidden }` as JSON data under `alford:game-pref:v1:<slug>` in UserDefaults. The preference store is separate from the ledger and WebKit puzzle saves. Hiding, starring, and the existing progress reset do not remove these collection choices. Invalid preference data falls back to unstarred and visible.

At document start, `window.__ALFORD_NATIVE__.gamePreference` contains `{slug,favorite,hidden}`. A bundled game may send `{type:'gamePreference',slug,favorite,hidden}` through the existing `alford` bridge. The decoder requires the trusted active main frame, the exact current game slug, and genuine booleans. Native changes synchronize the matching WebKit localStorage key and dispatch `alford:game-preference-change` with the same flat detail object. Web listeners must not echo native events. Reload refreshes the startup marker.
